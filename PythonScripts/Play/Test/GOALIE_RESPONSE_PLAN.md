# GoalieOnly 门将动态响应参数测试

## 目的

测量 `GoalieOnly` 面对移动来球时的响应延迟、实际移动速度、加速度和跟随误差，为之后的射门角度预测提供参数。本轮只采集门将动态响应；不单独验证椭圆几何，也不改正式策略或 `InterceptAndShoot`。

采用已知的门将站位假设作为分析参考：球门中心与球的连线和半轴 `x=300 mm`、`y=500 mm` 的椭圆相交，交点是预测站位。逐帧把按该假设算出的参考点写入遥测，供后续拟合时比较实际站位；参考点误差不作为本轮通过/失败条件。

## 试验设计

黄方运行 `GoalieOnly`，只让 0 号机器人执行 `Skill.Goalie()`；蓝方机器人 0、1、2 固定在 `x=-3800 mm`、`y=-2200/0/2200 mm`，其余机器人禁用。每组开始时把黄方门将放在正 X 球门前方 `300 mm` 的椭圆轴端，球放在给定起点并静止。等待 `0.8 s` 让视觉稳定后，只更新球的初速度，不重置门将，以便观测同一次运动响应。

球从 `x=1500、2800 mm`、`y=0` 出发，瞄准正 X 门线上的五个横向落点。横向位置取当前安全半门宽 `Params.goalWidth/2 - 90 mm` 的 `-85%、-42.5%、0、42.5%、85%`。球速请求为 `2、5、6 m/s`，每种条件重复两次，总计 `2 × 5 × 3 × 2 = 60` 次。场地尺寸和门线从运行时 `Params` 读取，因此门将重置位置也会随大小场参数变化；当前小场配置下安全半门宽为 `410 mm`，五个目标约为 `-348.5、-174.25、0、174.25、348.5 mm`。

测试顺序使用固定随机种子打乱，减少按球速或目标顺序运行带来的系统性偏差。单次最多观测 `3.5 s`；若球没有到达门线，该次仍保留，并按实测球速和实际轨迹分析，不算作高速用例已验证。

## 记录与参数估计

脚本逐帧记录时间、视觉 cycle、球与门将的位置和速度、有效标志、门将速度矢量差分得到的加速度、椭圆参考站位及两者距离。每次结果另外记录请求及实测球速、门将开始移动时间、门将速度和加速度的峰值与第 95 百分位，以及球门线交点的时间、横坐标和门将位置。

门将开始移动定义为速度达到 `100 mm/s`，或相对发球时位置移动至少 `20 mm`，并连续两帧满足；时间从初速度更新时开始计。加速度遥测按相邻帧门将速度作有限差分。有限差分对视觉噪声敏感，拟合前应按实测时间戳平滑速度，再计算加速度；不要直接用单帧峰值当作物理最大加速度。

分析时用球的实测位置/速度重建逐帧目标输入，并按目标横向变化分组。先估计响应延迟，再从平滑后的速度曲线估计可持续速度上限；从起动阶段拟合加速度，从目标趋稳或低速轨迹中的减速阶段估计制动能力。报告中同时给出每个用例和汇总分位数，区分请求球速与实际达到的球速。若本轮轨迹没有足够的减速段，则制动参数标记为待测，不外推。

## 运行方法

在 `mark_i` 目录执行：

```powershell
.\run_goalie_response.ps1
```

脚本检查项目虚拟环境是否为 Python `3.12.10`，必要时启动 `grSim.exe` 和 `Client.exe`，再用黄方、右半场、仿真模式启动独立采集入口。运行前在 grSim 中确认使用本轮所需场地配置、仿真正常连接视觉。脚本等待全部试验结束，最长等待 12 分钟。

输出写入 `robocup/tmp/goalie_response_<run-id>/`：`telemetry.jsonl` 为逐帧记录，`results.json` 为每次试验汇总，`stdout.log` 和 `stderr.log` 为运行日志。启动入口在运行时替换内存中的 `Config.testStrategy`，不编辑 `Config.py`；主程序退出后，启动脚本按原始字节恢复 `zss.ini`。

试验完成后，从 `mark_i` 目录离线生成参数汇总：

```powershell
& .\PythonScripts\.venv\Scripts\python.exe .\PythonScripts\Play\Test\analyze_goalie_response.py ..\tmp\goalie_response_<run-id>
```

分析器生成 `analysis_summary.md`、逐次指标 `trial_metrics.csv`、按球速汇总的 `speed_summary.csv`、按球速和目标位置汇总的 `speed_target_summary.csv`，以及完整 `analysis.json`。它对门将速度作五帧中值平滑，再用实测时间戳差分估算加速度；原始遥测不被覆盖。

## 交付与边界

本轮脚本只发球并运行黄方门将策略，不运行蓝方接球/射门策略，不评估进球率，也不改动 `two_attack`、`InterceptAndShoot` 或全局控球判定。拿到并检查这 60 次门将响应数据后，再据此确定联合选点所需的门将延迟、速度和加速度参数；之后是否进入接球和射门 A/B 测试，仍由用户确认。
