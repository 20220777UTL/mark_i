默认开局 → 底角 → 回传迎球直射（禁止重新吸球找球版）

这是新增的完整流程测试，与旧的手动底角摆球测试分开。
使用软件默认场地和默认静止球位置，不需要先把球放到底角。
依然要求策略 Params 的场地尺寸与实际模拟器一致；脚本不会自动读取或更改模拟器场地尺寸。
只控制蓝队1、2号，其他机器人移除或远离路线。两车必须可见、在场内且不在对方禁区。
以我方在左侧、朝右侧球门进攻进行验证。只启动蓝队策略，黄队不开。

Windows 最短操作
1. 同步 test/corner-pass-shot 分支。先保存自己的本地改动，不强制覆盖。
2. 关闭旧 Client 和本次测试旧 Medusa 进程。
3. 双击仓库根目录 start_give_and_go.cmd（与 Client.exe 同一级）。
4. 在这个新开的 Client 中启动 Simulator → 连接，恢复默认静止球和两车。
5. 点击蓝队 Medusa。角色按开局1、2号距球远近自动确定，同距时1号为近车。
6. 录下整轮过程和 [give-and-go] 日志。单轮结束后保持停止。

启动脚本只设置本次 Client 及子进程的测试开关，不会安装/修复 Python 或 DLL。
请使用原来已能运行测试的 Windows 软件环境。若程序报错，将原始报错发回。
如果要在 PowerShell 手动启动，在仓库根目录执行：
  $env:SRC_GIVE_AND_GO_TEST = "1"
  .\Client.exe
新开关优先于旧 SRC_CORNER_PASS_TEST，旧测试文件和比赛策略保留。
普通启动不设置新开关时，不会自动进入新流程。

动作顺序
SETUP：开局一次性分配角色。近车去取球，红外+球口距离确认控球后锁定车身位置，
只调整朝向并等待；远车跑到右下底角，面向近车准备接球。此时不会自动踢球。
双方到位、近车控球且方向正确，稳定0.25秒后进入 PASS_OUT。
PASS_OUT：近车向远车球口平传。发出踢球请求后不继续追球；检测到球朝接应方向离开才换阶段。
RETURN_SETUP：近车跑到禁区线外射门点，预先朝球门；远车先在底角等待，来球进入附近后取球，
控球后留在接球位置转向射门点，等近车站稳后再回传。
RETURN_PASS：远车向近车球口平传。检测到球离开后立即进入 FINISH。
FINISH：近车根据来球速度预测接触点，在射门点周围300 mm内小幅迎球并提前调整朝向。
只使用 SimpleGoTo 和显式 kickStatus.setKick，不调用 StaticGetBall，不读取红外持球状态，吸球为0。
球进入实际球口的前向/侧向窗口且朝向达标时，预触发平射；远车停止。
踢球请求发出后锁定位置和朝向，最多0.18秒内仅在球口条件仍满足时补发同一脚请求。
此后直接结束，不能重新吸球、转身找球或追球补射。
DONE：保持停止，日志给出结束原因。

这不是裁判盒 KickOff 状态机：在 isTestMode 下点击蓝队策略就开始取球流程，
无需额外下发开球命令。是从默认摆球开始的完整动作实验，不能直接作为正式比赛开球合规策略。

站位由代码 Params 计算，单位 mm
底角接应车中心：(pitchLength/2-600, -pitchWidth/2+600)
射门车中心：(pitchLength/2-penaltyDepth-350, 0)
传球瞄准接应车朝向一侧、距车身中心 playerFrontToCenter+22 的球口位置。
近车不会将球运到底角，而是取球后原地等待传球；两次传球都使用 evalPower(P.NORMAL)，平传。
最后接射使用 evalPower(P.HIGH)，实际是否触球即出脚需要录像验证，发出指令不等于成功射门。
远车第一脚接球采用基础移动+吸球，然后原地转向回传，不要求第一脚也一脚转传。

运行检查
角色一旦分配不再交换。近车红外未检测到持球时，不会进入第一脚传球。
远车没控住球，或射门车没站好时，不会回传。日志中 kick requested 只是发出请求，不证明球已踢出。
SETUP 35秒，PASS_OUT 8秒，RETURN_SETUP 18秒，RETURN_PASS 8秒，FINISH 6秒，超时即停止。
角色分配后视觉丢失、球出界、任一车接近对方禁区边界也会停止。
禁区检查是每帧停止条件，不是底层规划器的绝对避障保证。
模拟器默认球如果已运动或上轮球已出界，请先复位；脚本不自动重新摆球。

停止、重试和恢复
测试模式不能依赖裁判盒 Stop；停止该队 Medusa 并暂停模拟器确认停车。
重试：停止旧策略 → 恢复默认球和车 → 再启动蓝队策略。
退出新测试：关闭测试 Client，从普通入口新启动 Client；若手动设置过 PowerShell 变量，清除：
  Remove-Item Env:SRC_GIVE_AND_GO_TEST -ErrorAction SilentlyContinue
若还设置过旧 SRC_CORNER_PASS_TEST，也清除它再恢复正常策略。

最后接射的独立调试参数（Test_GiveAndGo.py 顶部）
MEET_RADIUS=300 mm：接射车中心允许移动的区域半径，围绕固定射门等待点。
MEET_LEAD_TIME=0.06 s：相对来球穿过名义球口x坐标的时刻，提前迎球的预测时间。
MIN_INCOMING_SPEED=150 mm/s：低于此速度结束本轮，不主动取球。
KICK_SIDE_TOLERANCE=40 mm：来球相对实际车身朝向的横向误差窗口。
KICK_FRONT_MARGIN=55 mm：名义球口前方的预触发距离余量。
KICK_ANGLE_TOLERANCE=8度：车身朝向与计划射门朝向的最大误差。
KICK_WINDOW_SECONDS=0.18 s：第一次踢球请求后最多保持的短触发窗口。
触发使用实际球口位置和来球方向，不使用红外持球条件。
预测点越出区域、球已经错过接球线、球停住或不再向接球线运动时停止，不做补救。
以上均为待标定的实验参数，不代表已经实测的最佳值或精度保证。
先保持默认参数录像，再分别标定回传力度、站位和触发窗口，避免一次改多个参数。
