这是“蓝方传射 + 黄方守门”的单轮模拟测试补丁。
请使用此前录像中已经能跑通的 Windows 比赛软件环境，不要重新安装 Python 或替换 DLL。

更新方法（二选一）
A. Git：先保存自己的修改，在仓库根目录执行：
   git fetch origin
   git switch test/corner-pass-shot
   git pull --ff-only
   若本地修改冲突或不能快进，停止并发回提示，不要强制覆盖。
B. ZIP：先备份自己的代码和 PythonScripts/Config.py，再按原目录结构合并到已跑通的仓库。
   确认 start_give_and_go.cmd 与 Client.exe 在同一层。补丁不含 exe、dll 或虚拟环境，不能独立运行。
   不要删除原有 PythonScripts 文件夹；Config.py 有自己的改动时先比较合并。

启动步骤
1. 停止旧策略，关闭旧 Client 和旧测试 Medusa。
2. 双击 start_give_and_go.cmd。直接打开普通 Client.exe 不会自动启用此测试。
3. 在新 Client 中启动 Simulator 并连接，使用默认场地、默认静止球。
   蓝队1、2号在场内、对方禁区外；黄队0号在右侧球门附近；其余车辆移出传射路线。
   蓝队守左攻右，黄队守右攻左；两队半场设置相反。Params 场地尺寸须与模拟器一致。
4. 用裁判控制将状态设为比赛进行中（FORCE_START / 强制开始）。自带守门技能需要该状态。
5. 先启动黄队 Medusa，等日志出现：
   [src-test] YELLOW: Test_Goalie2022; robots=(0,)
6. 再启动蓝队 Medusa，日志应出现：
   [src-test] BLUE: Test_GiveAndGo; robots=(1, 2)
   随后会有 [give-and-go] 流程日志。不要同时快速连点两队启动按钮。
7. 录下整轮过程和两边日志。若两边显示同一颜色、旧策略名称或报错，先停止测试并保留完整提示。

动作：近车球后对准（不开吸球）→ 远车到底角 → 首传 → 近车跑射门点 → 远车回传 → 近车迎球直射。
最后阶段不吸球、不找球补射；偏球或超时结束本轮。黄方使用软件包自带 Goalie2022，
不能据此认定它就是初赛官方两阶段守门策略。当前也不保证每次必然触球或进球。

停止与重试
本测试绕过 Python 裁判策略，不要只依赖裁判盒 Stop 停车。
停止双方 Medusa 并暂停模拟器，确认停车。恢复默认静止球及合法车位，再按黄队、蓝队顺序启动。
蓝方是单轮流程，DONE 后不会自动重新摆球；黄方守门策略不会随蓝方 DONE 自动关闭。
若启动时提示旧 Client 在运行，先退出旧 Client。单独更新代码不会改变已经启动的进程。
